ESP32 Matter basis

Zelf een slimme Matter-sensor maken: installatie, valkuilen en Hello World

Voordat je een eigen Matter-sensor bouwt, moet eerst de ontwikkelomgeving kloppen. In deze tutorial zetten we ESP-IDF klaar, testen we Hello World en lossen we de valkuilen op die je onderweg kunt tegenkomen.

Een eigen Matter-sensor bouwen klinkt alsof je meteen met sensoren, clusters en smart home-platformen aan de slag gaat. In de praktijk begint het veel eenvoudiger: eerst moet je zeker weten dat je ESP32 goed wordt herkend, dat ESP-IDF werkt en dat je een klein testprogramma kunt flashen.

In deze tutorial gebruiken we een ESP32 DevKit V1 als basis. Het einddoel is een eigen Matter-sensor, waarschijnlijk met een BME280 voor temperatuur, luchtvochtigheid en luchtdruk of een BH1750 voor lichtmeting. Maar voordat die sensor slim kan worden, testen we eerst de volledige ontwikkelketen met Hello World.

Wat leer je in deze tutorial?

Je leert hoe je van een lege start naar een werkende ESP-IDF testopstelling gaat. De nadruk ligt niet alleen op klikken en commando’s uitvoeren, maar vooral op begrijpen wat je ziet wanneer iets goed of fout gaat.

  • ESP-IDF werkend krijgen → je installeert en gebruikt de ESP-IDF omgeving in VS Code om een project te configureren, te bouwen en te flashen.
  • Hello World interpreteren → je controleert via de monitor of de ESP32 echt jouw firmware draait en wat de belangrijkste regels in de output betekenen.

Aan het einde heb je geen Matter-sensor, maar wel de noodzakelijke basis om die sensor verantwoord te gaan bouwen. Dat voorkomt dat je later Matter-fouten probeert op te lossen terwijl eigenlijk je toolchain, poort of flashconfiguratie niet goed stond.

Voor wie is deze tutorial?

Deze tutorial is bedoeld voor makers die al ervaring hebben met Arduino of ESP32-projecten, maar nu de stap willen zetten naar ESP-IDF en Matter. Je hoeft nog geen Matter-code te begrijpen, maar je moet wel bereid zijn om iets dichter op de ontwikkelomgeving te werken dan bij een gewone Arduino-sketch.

Wat heb je nodig?

  • ESP32 DevKit V1
  • USB-datakabel, geen kabel die alleen kan laden
  • Windows-pc met Visual Studio Code
  • ESP-IDF extensie van Espressif Systems in VS Code
  • Een eerste sensor voor de vervolgstap, bijvoorbeeld BME280 of BH1750

Stap-voor-stap uitleg

1. Installeer ESP-IDF en open het voorbeeldproject

Installeer in VS Code de officiële ESP-IDF extensie van Espressif Systems. Deze extensie voegt de belangrijkste knoppen en opdrachten toe voor builden, flashen, monitoren en configureren. Open daarna het voorbeeldproject hello_world vanuit de ESP-IDF voorbeelden of vanuit je eigen projectmap.

  • Open de projectmap waarin onder andere CMakeLists.txt, sdkconfig en de map main staan.
  • Gebruik in VS Code de Command Palette met Ctrl + Shift + P.
  • Kies ESP-IDF: Set Espressif Device Target en selecteer voor de ESP32 DevKit V1 het target esp32.

2. Controleer of het project configureert en buildt

Na het instellen van het target maakt ESP-IDF een buildmap aan en configureert CMake het project. In ons geval eindigde dit met de melding Target ESP32 Set Successfully. Dat is een belangrijk signaal: de ESP-IDF installatie, compiler, Python-omgeving en projectstructuur werken samen. Meldingen over git describe of losse componentmappen zonder CMakeLists.txt zijn bij dit eenvoudige project niet direct een probleem.

3. Los de eerste echte blokkade op: geen seriële poort

De eerste echte fout was No serial ports found. Dat betekent niet dat je code fout is, maar dat Windows of VS Code je ESP32 nog niet als COM-poort ziet. De oorzaak zit meestal in een USB-kabel zonder datalijnen, een ontbrekende USB-serial driver of een verkeerde USB-poort. Zodra het board wel zichtbaar werd, konden we COM10 selecteren en de monitor openen.

#include <stdio.h>
#include "freertos/FreeRTOS.h"
#include "freertos/task.h"
#include "esp_chip_info.h"
#include "esp_flash.h"
#include "esp_system.h"

void app_main(void)
{
    printf("Hello Mike, lekker bezig!\n");

    esp_chip_info_t chip_info;
    uint32_t flash_size;

    esp_chip_info(&chip_info);
    esp_flash_get_size(NULL, &flash_size);

    printf("This is %s chip with %d CPU core(s), WiFi/BTBLE, silicon revision v%d.%d, %luMB external flash\n",
           CONFIG_IDF_TARGET,
           chip_info.cores,
           chip_info.revision / 100,
           chip_info.revision % 100,
           flash_size / (1024 * 1024));

    printf("Minimum free heap size: %lu bytes\n", esp_get_minimum_free_heap_size());

    while (1) {
        printf("ESP-IDF draait nog steeds netjes...\n");
        vTaskDelay(5000 / portTICK_PERIOD_MS);
    }
}

4. Flash Hello World en lees de monitor-output

Na het flashen start de ESP32 opnieuw op en zie je in de monitor de bootloader, chipinformatie en uiteindelijk de regel Hello world. Dat is het bewijs dat de firmware echt op het board draait. In ons geval verscheen daarna ook de informatie dat het om een ESP32 met twee CPU-cores, WiFi/Bluetooth en externe flash ging.

5. Zet de flashgrootte goed en pas zelf de code aan

De monitor liet eerst zien dat het board 4 MB flash had, terwijl de firmware nog op 2 MB stond ingesteld. Dat hebben we aangepast via de SDK Configuration Editor bij Serial flasher config. Daarna verdween de waarschuwing en gaf de monitor netjes 4MB external flash aan. Vervolgens hebben we Hello World aangepast naar Hello Mike, lekker bezig! en daarna het herstartgedrag vervangen door een loop die elke paar seconden een bericht print.

Integratie met Homey

De Homey-integratie komt pas in een latere stap. Het doel is uiteindelijk een sensor te bouwen die via Matter beschikbaar kan komen in een smart home-platform. Daarvoor moet de basis eerst kloppen: ESP-IDF moet kunnen builden, flashen en betrouwbaar communiceren met het board.

Denk bij het vervolg aan sensoren die in huis direct praktische waarde hebben:

  • Een BME280 als temperatuur-, luchtvochtigheids- en luchtdruksensor voor een kamer.
  • Een BH1750 als lichtsensor voor automatische verlichting of zonlichtdetectie.
  • Een latere combinatie met CO₂- of aanwezigheidssensoren voor slimmere ventilatie- en lichtflows.

Wat kun je hierna?

Na deze stap kun je gericht verder met een I2C-scanner. Daarmee controleer je eerst of de BME280 of BH1750 op de juiste I2C-adres wordt gevonden. Pas daarna is het logisch om sensorwaardes uit te lezen en deze later aan een Matter-datamodel te koppelen.

Veelgemaakte fouten en aandachtspunten

  • Gebruik een echte USB-datakabel. Een laadkabel kan ervoor zorgen dat er geen COM-poort verschijnt.
  • Controleer de flashgrootte. In dit project stond de firmware eerst op 2 MB terwijl het board 4 MB flash had.
  • Begin nog niet met Matter zolang Hello World, build, flash en monitor niet probleemloos werken.

Conclusie

De belangrijkste winst van deze eerste stap is vertrouwen in de basis. De ESP32 DevKit V1 wordt herkend, ESP-IDF bouwt het project, de firmware wordt geflasht en de monitor toont onze eigen aangepaste tekst. Daarmee is de weg vrij om in de volgende stap een I2C-sensor zoals de BME280 of BH1750 uit te lezen en daarna pas richting een echte Matter-sensor te gaan.
